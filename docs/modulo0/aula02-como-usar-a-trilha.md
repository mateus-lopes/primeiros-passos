# 0.2 · Como usar esta trilha

!!! abstract "Hoje você vai…"
    Entender como as lições funcionam, o que fazer quando travar e como procurar respostas sozinha. ⏱️ ~1h

---

## Os nossos combinados 🤝

### 1. Sem pressa, de verdade

Cada lição leva mais ou menos **1 hora**. Se levar 2, tudo bem. Se precisar ler duas vezes, tudo bem também. Ninguém aprende a fazer um bom brigadeiro na primeira panela.

Você estuda de **terça a quinta, à tarde**. Segunda e sexta são de descanso: o cérebro também precisa de tempo para guardar o que aprendeu.

### 2. A regra dos 15 minutos ⏰

Vai acontecer de você travar em alguma coisa. Isso é **normal** e acontece com todo programador, todo dia, inclusive os experientes.

Quando travar:

1. Tente resolver sozinha por **até 15 minutos**: releia a lição, procure no MDN (já já você vai ver como).
2. Não saiu? **Anote a dúvida** no seu arquivo `DUVIDAS.md`.
3. Siga para a próxima parte, ou pare por hoje. **As duas opções estão certas.**

Travar não quer dizer que você não leva jeito. Quer dizer que você está aprendendo uma coisa nova.

### 3. Sem inteligência artificial 🚫🤖

Nesta trilha, **você não usa IA** (ChatGPT, Copilot, Gemini e afins) para fazer as lições nem os desafios.

Não é por implicância. É que aprender a programar funciona igual à academia: **se outra pessoa levantar o peso por você, o seu músculo não cresce**. A IA entrega a resposta pronta, e aí o seu cérebro pula justamente a parte que faz aprender: pensar, tentar, errar e tentar de novo.

Depois que você souber programar, a IA vira uma ferramenta ótima. Mas primeiro vem o músculo. 💪

## Como cada lição funciona

Todas as lições seguem o mesmo jeitinho, para você sempre saber onde está:

| Parte | O que é |
|---|---|
| **Hoje você vai…** | O que você vai fazer e quanto tempo leva |
| **Explicação** | O assunto do dia, sem palavras difíceis |
| **Exemplo pronto** | Algo já feito para você ler, entender e testar |
| **Mexe aí** ✏️ | Pequenas mudanças no exemplo, para ver o que acontece |
| **Desafio** 🎯 | Uma tarefinha para entregar no seu repositório |
| **Checklist** ✅ | O que você aprendeu hoje |

Toda palavra técnica nova vai para o [**Glossário**](../glossario.md). Se esquecer o que alguma coisa significa, é só dar uma olhada lá.

## Entregando os desafios 📦

Cada desafio fica numa pasta com o número da lição, dentro do seu repositório `desafios`:

```
desafios/
├── DUVIDAS.md
├── desafio-0.1/
│   └── sobre-mim.txt
├── desafio-0.2/
│   └── ...
```

Quando terminar um desafio, faça o **ritual de entrega** no terminal do VS Code:

```bash
git add .
git commit -m "Desafio 0.2: o que eu fiz"
git push
```

Depois, quem te acompanha vai olhar o que você entregou e vocês corrigem **juntos**. Não é prova e não vale nota. É conversa. 😊

!!! tip "Entregue mesmo que não esteja perfeito"
    Desafio pela metade também se entrega. Um desafio incompleto mostra exatamente onde você precisa de ajuda, e isso é muito útil.

## Procurando respostas no MDN 🔎

Sem IA, onde procurar quando bater uma dúvida? No **MDN**, a "enciclopédia" oficial da programação para a web. É lá que programadores do mundo inteiro tiram dúvidas, e ele tem versão em português.

📖 **[developer.mozilla.org/pt-BR](https://developer.mozilla.org/pt-BR/)**

### Dicas para pesquisar

- **Use a busca do próprio MDN**, no topo da página. Ela é mais certeira que o Google.
- Se for usar o Google, coloque **"MDN"** na pesquisa. Exemplo: `MDN tag img`.
- **Pule o resumo de IA** que o Google mostra no topo dos resultados, pelo mesmo motivo do combinado 3. 😉
- Algumas páginas ainda estão só em inglês. Tudo bem usar o tradutor do navegador (clique com o botão direito → **Traduzir para o português**).
- O **Glossário do MDN** é ótimo para palavras soltas: **[developer.mozilla.org/pt-BR/docs/Glossary](https://developer.mozilla.org/pt-BR/docs/Glossary)**

### Exemplo pronto

Vamos procurar juntas o que é **navegador**:

1. Abra o MDN e digite `navegador` na busca.
2. Entre na página do Glossário sobre **navegador** (*browser*).
3. Leia o primeiro parágrafo.

Viu? É o programa que você usa para abrir sites, como o Chrome, o Edge ou o Safari. Agora você sabe usar o MDN. 🎉

### ✏️ Mexe aí

Use a busca do MDN para descobrir o que é **URL**. Leia só o começo da explicação. Você usa URLs o tempo todo, mesmo sem saber o nome! (Dica: tem a ver com a barra de endereço do navegador.)

## 🎯 Desafio 0.2

Crie a pasta `desafio-0.2` com um arquivo `mdn.txt` dentro. Procure no MDN e escreva, **com as suas palavras** (nada de copiar e colar!), uma ou duas frases sobre cada uma:

1. O que é **HTML**?
2. O que é **CSS**?
3. O que é **JavaScript**?

Essas são as três linguagens que você vai aprender na trilha. Não precisa entender tudo agora: é só para ter uma primeira ideia.

Depois, faça o ritual de entrega. 📦
